# ایجنت داخلی پیشخوان

این بخش یک حلقه واقعی مدل و ابزار است. پیام به یک مدل سازگار با Chat Completions فرستاده می‌شود، مدل ابزارهای ثبت‌شده در پروژه را انتخاب می‌کند، نتیجه واقعی همان ابزارها به مدل برمی‌گردد و حلقه تا پاسخ نهایی یا سقف مراحل ادامه دارد. چت‌بات مبتنی بر کلیدواژه یا نتیجه ساختگی به عنوان جایگزین مدل وجود ندارد.

## تنظیم مدل

در `.env` این مقادیر را تنظیم کنید:

```dotenv
AGENT_BASE_URL=https://your-model-provider.example/v1
AGENT_MODEL=your-tool-calling-model
AGENT_API_KEY=
AGENT_MAX_STEPS=12
AGENT_TIMEOUT=90
```

آدرس بالا نمونه است. `AGENT_BASE_URL` باید ریشه API باشد؛ برنامه `/chat/completions` را به آن اضافه می‌کند. مدل باید `tools` و پاسخ‌های `tool_calls` را با قرارداد Chat Completions پشتیبانی کند. کلید API برای ارائه‌دهنده‌ای که احراز هویت می‌خواهد تنظیم می‌شود؛ برای یک مدل محلی بدون احراز هویت می‌تواند خالی بماند. مقدار `AGENT_MAX_STEPS` بین ۱ و ۵۰ است و تعداد درخواست‌های مدل در هر نوبت را محدود می‌کند. timeout برای هر درخواست اعمال می‌شود، نه کل گفت‌وگو.

بدون تنظیم آدرس و مدل، پاسخ ساختاریافته `agent_not_configured` برمی‌گردد. هیچ سرویس مدل، حساب یا اشتراک خارجی به طور خودکار ساخته نمی‌شود.

## اجرا

ابتدا از رابط ایجاد جلسه پروژه یک `session_id` بگیرید. سپس:

```bash
python manage.py agent 'خدمات مربوط به قبض را نشان بده' --session SESSION_UUID
python manage.py agent 'نیازمندی‌های قبض برق را بررسی کن' --session SESSION_UUID --conversation CONVERSATION_UUID
```

شناسه گفت‌وگو در پاسخ نوبت اول برمی‌گردد. برای ارسال متن از stdin، آرگومان پیام را حذف کنید. برای ورودی‌هایی مانند OTP یا رمز، واردکردن تعاملی در رابط چت یا stdin از قرارگرفتن مقدار در آرگومان خط فرمان جلوگیری می‌کند.

رابط Python که view چت نیز استفاده می‌کند:

```python
from apps.agent.runner import run_turn

result = run_turn(
    session_id="existing-session-uuid",
    message="قبض برق ذخیره‌شده را بررسی کن",
    conversation_id=None,
)
```

پاسخ شامل `ok`، `reply`، `conversation_id`، حالت `demo/live`، تعداد مراحل و trace ابزارهای اجراشده است. در خطا، `error.code` و `stop_reason` علت توقف را مشخص می‌کنند. نتیجه عملیات اجراشده ممکن است حتی پس از خطای مدل یا رسیدن به سقف مراحل معتبر باشد؛ پیش از تکرار، وضعیت همان عملیات بررسی شود.

## رفتار اجرایی

- منبع ابزارها همان `apps.core.tools` است که MCP و API پروژه استفاده می‌کنند؛ مسیر اجرایی موازی و جداگانه‌ای برای مدل وجود ندارد.
- جلسه از درخواست برنامه به ابزار تزریق می‌شود و از schema نمایش‌داده‌شده به مدل حذف شده است. مدل نمی‌تواند گفت‌وگوی یک حساب را به حساب دیگری وصل کند یا از ابزار ایجاد جلسه برای تغییر حساب استفاده کند.
- ورودی ابزار با JSON Schema اصلی اعتبارسنجی می‌شود. فراخوانی نامعتبر یا ابزار ناشناخته به شکل نتیجه خطا به مدل برمی‌گردد.
- برای ابزار دارای فیلد `idempotency_key`، اگر مقدار موجود نباشد، یک کلید مشخص از شناسه گفت‌وگو، نوبت و فراخوانی تولید می‌شود. تکرار یک شناسه فراخوانی در همان نوبت دوباره اجرا نمی‌شود. جلوگیری نهایی از برداشت تکراری همچنان بر عهده لایه عملیات و تأمین‌کننده است.
- فراخوانی‌ها به ترتیب اجرا می‌شوند و تمام پاسخ‌های ابزار قبل از درخواست بعدی مدل به تاریخچه اضافه می‌شوند.
- متن نتیجه ابزار در نقش `tool` نگه داشته می‌شود و پیام system جدا است. prompt ایجنت داده تأمین‌کننده را دستور جدید محسوب نمی‌کند.
- نتایج demo باید در پاسخ به عنوان آزمایشی معرفی شوند. وجود یک ردیف در کاتالوگ، اثبات اجرای زنده آن نیست.

## OTP، رمز و تاریخچه

ایجنت می‌تواند OTP یا password ارائه‌شده در نوبت جاری را به ابزار احراز هویت مرتبط بدهد. چنین ورودی‌ای هنگام استفاده از مدل خارجی به همان ارائه‌دهنده مدل هم فرستاده می‌شود؛ برای جریان بدون ارسال رمز به مدل، ابزار ورود را مستقیم از رابط برنامه فراخوانی کنید و سپس گفت‌وگو را ادامه دهید.

فیلدهای شناخته‌شده رمز، OTP و توکن و مقادیری که در آن‌ها استفاده شده‌اند از تاریخچه ذخیره‌شده و trace عمومی حذف می‌شوند. این قابلیت یک تشخیص‌گر عمومی برای همه انواع داده شخصی نیست. تشخیص متن آزاد ممکن است کامل نباشد؛ رمز استفاده‌نشده و بدون برچسب قابل تشخیص قطعی نیست. برنامه عمداً اطلاعات اتصال را در log چاپ نمی‌کند. توکن برگشتی احراز هویت برای ادامه کار در جلسه دامنه باقی می‌ماند و لازم نیست در متن پاسخ مدل بازگو شود.

## آزمون

```bash
pytest tests/test_agent.py -q
```

آزمون‌ها transport مدل را شبیه‌سازی می‌کنند و خود حلقه، ترتیب فراخوانی‌ها، اتصال حساب، سقف مراحل، خطاها و حذف اطلاعات ورود از تاریخچه را بررسی می‌کنند. این آزمون‌ها به معنی تست موفق یک مدل خارجی یا اجرای تراکنش واقعی نیستند.

مرجع قالب درخواست و پاسخ مدل: [Chat Completions API reference](https://developers.openai.com/api/reference/resources/chat). ارائه‌دهنده سازگار باید زیرمجموعه مورد استفاده این پروژه را پشتیبانی کند.
